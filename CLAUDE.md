## Project notes

- **Stack:** Next.js 16 (Turbopack, `src/proxy.ts` instead of middleware), Prisma 7 with the `@prisma/adapter-pg` driver adapter, Supabase Postgres and Supabase Auth via `@supabase/ssr`. Progress log: `docs/implementation-status.md`.
- **Database:** the shared Supabase project `tfkazskwrarwbjdtlqed` hosts several apps. This app owns only the `invoicetracker` schema and connects as the `invoicetracker` role through the Session pooler (`?schema=invoicetracker` in `DATABASE_URL`). Never touch other schemas (for example `rentflow`) or project-wide Auth settings without asking. Tables have RLS enabled with no policies on purpose: the app connects as the owner and nothing should be reachable through the Data API.
- **Migrations:** Prisma Migrate owns the schema (`npm run db:migrate`). Generate SQL with `npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script`; `migrate dev` needs a shadow database the role cannot create.
- **Auth:** all Supabase Auth calls run on the server (`src/lib/auth.ts`, `src/app/api/auth/[action]`, `src/app/auth/callback`). Pages use `requireSession()`, API routes use `getApiWorkspace()` or `getSession()`. `SUPABASE_SECRET_KEY` is server-only, always required, and must never get a `NEXT_PUBLIC_` prefix.
- **Auth emails:** the app sends signup, reset and resend-verification emails itself (`EMAIL_MODE`; `file` writes to `.local/mail`). Links carry a `token_hash` from `admin.generateLink` and `/auth/callback` calls `verifyOtp`, so they work on any device. Don't switch back to Supabase's emails: its PKCE links only work in the requesting browser and its templates are project-wide.
- **Shared Auth is settled:** `auth.users` is shared with rentflow because the free tier allows only two projects. One login works in both apps and the secret key is project-wide. Don't suggest a separate project.
- **Session cookies:** pass every cookie write through `withSessionLifetime` (`src/lib/session-cookie.ts`); `@supabase/ssr` ignores `cookieOptions.maxAge` and writes 400 days. Sign-out is `scope: "local"`; only password reset signs out everywhere.
- **Origins:** compare request origins with `APP_URL` (`hasSameOrigin`), not `request.url`. In development Next reports `localhost` while the browser uses `127.0.0.1:3000`.
- **Checks:** `npm run lint`, `npm run typecheck`, `npm test`; with the dev server running, `npm run test:integration` and `npm run test:e2e`. The latter two need `REQUIRE_EMAIL_VERIFICATION=false` and `SUPABASE_SECRET_KEY`, and delete the Supabase accounts they create.
- **Local database for tests:** remote Supabase is too slow for the e2e journey (~150 ms per round trip from here). Run `npm run db:local` and use the commented `# DATABASE_URL=` (127.0.0.1:54329) line in `.env`, as CI does. If `next dev` loops on Fast Refresh after a `next build`, delete `.next`. On Windows, stopping a background dev server can leave orphan `node`/`postgres` processes; stop postgres with `pg_ctl stop -D ~/.invoice-tracker/postgres -m fast`.
- **CI and Git:** `.github/workflows/ci.yml` needs repository variables `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` and the secret `SUPABASE_SECRET_KEY` (all set). Work on a branch, open a PR to `main`, squash-merge.
- **Demo mode:** `DEMO_MODE=true` (`isDemoMode()` in `src/lib/env.ts`) runs the public demo with no Supabase or Resend keys (see `docs/deployment-render-demo.md`). Gate any behaviour that would reach a real provider or shared data on `isDemoMode()`. Classify every new write route in `tests/demo-routes.test.ts`, and add every new workspace-owned table to `DEMO_DELETE_ORDER` in `src/services/demo-cleanup.ts` (children before parents). Empty env values count as unset, so `SUPABASE_SECRET_KEY= RESEND_API_KEY=` turns the keys off for a local demo run. Never run the demo tests against the shared database.
- **Live demo:** https://invoice-tracker-demo.onrender.com (Render service `invoice-tracker-demo`, auto-deploys from `main`). Its database is `invoice_tracker_demo` inside rentflow's free `rentflow-demo-db` instance (one free Postgres per Render workspace); never touch the `rentflow_demo_db` database there. Rate limits key on `True-Client-IP` in demo mode, because Render's `X-Forwarded-For` ends in proxy hops.
